## Code Review: java-guard (Java 静态扫描工具, Rust)
- 实测 `cargo test --workspace` 全绿，43 个测试通过（22 guard-core + 3 java-ast + 3 main + 3 plugin + 4 rhai + 8 yaml），e2e 通过（jar 已构建）。
- 之前 test_out*.txt 里的 serde recursion 编译错误是**陈旧日志**，当前代码已实现 `#![recursion_limit=1024]`，可正常编译。

主要问题（待修复）：
1. **bug**: `guard-core/src/reporter.rs` `chrono_now()` 时间戳格式错误，把 unix 秒当“当天秒” → `1970-01-01T00:00:1753987200Z`，JSON/SARIF 报表面时间戳全是非法值。
2. **健壮性**: `rule-yaml/src/matcher.rs` `match_fields` 对未知键 `_ => continue` 静默忽略，规则写错字段名（如 `name_regex`/`methd`）不产生任何告警也不命中，等于“隐形失效规则”。
3. **正确性**: 各 Pattern 递归深度不一致——MethodCall 全递归，但 MethodDeclaration/FieldDeclaration 只下钻一层嵌套类，深层嵌套类的方法/字段会被 J005/J007 漏掉。
4. **需求不符**: `rules/J001_no_system_out.yml` 仅匹配 `System.out.println`，漏掉 `System.err.*` 及 `print/printf`；文档要求的 `any_of`/`args_count` 未实现。
5. **文档漂移**: README 写“设计阶段未实现”、DEV_PLAN 写 M1，但实际 M5-M8 已完成；RULE_AUTHORING/TECHNICAL_DESIGN 描述的 Rhai API（`check(node,ctx)`/`node.children()`/`ctx.report()`）和 YAML schema（`callee:{any_of}`/`args_count`）与真实实现（注入全局 `ast` JSON + 返回数组；`match_fields` glob 字符串）完全不一致；消息占位符 `{name}` 等未实现。
6. **性能架构缺失**: 设计/需求要求的 DaemonParser（常驻 JVM）、AST 缓存、并行解析均未实现；实际 `CliParser` 每文件起一个 JVM 进程+临时文件，达不到 NFR 的秒级/10w行<10s 指标。
7. **小问题**: engine.rs 用 deprecated `as_string`（应为 into_string）、unused end_line、git_diff.rs unused `f`；main.rs `run_scan` ~280 行超长；仓库根目录散落 15 个 test_*.txt 应为构建产物应清理/忽略。

## 修复完成 (P0 → P2) 22:0x
按用户要求从 P0 到 P2 顺序修复，最终 `cargo test --workspace` 全绿（**50** 测试通过，0 失败）+ `cargo build` 零警告零错误。

### P0
- `guard-core/src/reporter.rs`: 删除非法 `chrono_now()`，改用自研零依赖 RFC3339 生成器 `format_rfc3339` + `yday_to_date`/`is_leap_year`/`yday_to_month_day`（迭代算法，已验证 epoch/纳秒/已知时间戳）。

### P1
- `rule-yaml/src/rule.rs`: 新增 `MatchValue` untagged enum（Single/Any）+ `YamlRule::validate()`（未知 match_fields 键 / 非法 severity 在加载时报警告并跳过，不再静默失效）。
- `rule-yaml/src/matcher.rs`: 重写 match 函数返回上下文 `Vec<(&str,String)>`；`value_matches` 支持 Single(精确/glob/regex) 与 Any(any_of)；新增 `render_message` 占位符替换；**统一 MethodDeclaration/FieldDeclaration 的嵌套类递归深度**与 MethodCall 一致。
